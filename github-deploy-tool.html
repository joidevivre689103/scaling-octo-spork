How it works

Drop one or more files onto the area above (or pick a whole folder). Each file’s repo path is pre-filled from its filename — you can edit each path inline before committing. Files ending in .dat are automatically gzipped to .dat.gz, matching the single-file Deploy flow. Everything lands in one atomic commit via the Git Trees API. GitHub token and Anthropic key are read from the Deploy tab.

7-G auto-inject: leave the checkbox ON. The injector is self-selective, so it never needs per-file judgement: non-HTML files pass through untouched; the exception pages (admin, cms, login, this tool, etc.) are skipped by id; already-stamped pages are detected and left alone or topped up — re-deploying anything is always safe. The checkbox is a kill-switch for rare debugging, not a per-file decision. The two cases that DO need thought happen when you create a new page, before its first injected deploy: (1) new public/gated page → add its page id to the right settings/featureGates bucket first (the gate fails closed — an injected page in no bucket bounces everyone, you included, to comingsoon); (2) new internal/tool page → add its id to CT_EXCEPTION_PAGE_IDS in this tool first, or it gets gated like content (the list is exact ids — a brand-new author-*.html still needs its own entry).
